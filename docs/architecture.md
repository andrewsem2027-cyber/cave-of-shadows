# «Пещера Теней»: архитектура проекта

Версия: 0.1  
Стек: Phaser 4, TypeScript, Vite

## 1. Решение

Архитектура проекта — **модульный монолит вокруг Phaser Scenes с небольшим
чистым доменным слоем**.

Мы используем возможности Phaser вместо создания второго игрового движка:

- Phaser управляет игровым циклом;
- Phaser Scenes управляют экранами и жизненным циклом уровня;
- Phaser Display List отвечает за отрисовку;
- Phaser Input принимает клавиатурный и сенсорный ввод;
- Phaser Arcade Physics используется для простых столкновений;
- Phaser Loader загружает изображения и звук;
- небольшие чистые TypeScript-модули содержат правила, генерацию и сериализуемое
  состояние.

Модель мира гибридная:

- структура этажа, стены, двери, ключи и pathfinding используют тайловую сетку;
- игрок и страж перемещаются плавно в мировых координатах;
- движение не пошаговое и не привязано к центрам клеток;
- при необходимости мировая координата переводится в клетку только для
  генерации, навигации и проверки проходимости.

## 2. Что берём из предложенной архитектуры

| Идея | Решение |
|---|---|
| Модульный монолит | Да |
| Отделение правил от отрисовки | Да, для логики, которую полезно тестировать |
| Конечные автоматы | Да, для поведения стража и состояния сессии |
| События | Да, только между сценой игры и интерфейсом |
| Интерфейс хранилища | Да, когда появятся сохранения |
| Компонентный подход | Только обычная композиция, без универсального ECS |
| Собственный Game Loop | Нет, его предоставляет Phaser |
| Собственный Renderer | Нет, его предоставляет Phaser |
| Абстракция над Canvas/WebGL | Нет |
| Сетевой порт | Нет, пока в проекте нет сети |
| Полная Clean/Hexagonal Architecture | Нет |
| ECS | Нет, для одного игрока и небольшого числа врагов избыточно |

## 4. Ответственность слоёв

### `game/scenes`

Сцены координируют игру:

- создают Phaser-объекты;
- связывают ввод, контроллеры и состояние;
- настраивают столкновения;
- управляют переходом между этажами;
- вызывают обновление систем.

Сцена не должна содержать весь алгоритм генерации уровня или сотни строк AI.

### `domain`

Обычный TypeScript без Phaser, DOM и браузерных API:

- сериализуемые данные;
- правила света;
- логика контрольных точек;
- генерация и валидация этажа;
- решение, что страж должен делать дальше;
- функции, которые удобно тестировать.

Допустимы числа, строки, массивы, объекты и простые типы координат.

### `world`

Тонкие оболочки над Phaser-объектами:

- внешний вид;
- размер и origin;
- физическое тело;
- позиция;
- простые визуальные эффекты;
- уничтожение объекта.

`GuardianObject` не решает самостоятельно, где искать игрока. Такое решение
принимает `GuardianController` с помощью доменных правил.

### `systems`

Контроллеры конкретных игровых механик:

- объединяют клавиатуру и touch в единое состояние ввода;
- включают и выключают бесконечный фонарь;
- обновляют преследование;
- обрабатывают взаимодействие с ключом, дверью и безопасной комнатой.

Один контроллер создаётся только тогда, когда соответствующая механика
появляется в игре.

### `services`

Граница с внешними возможностями браузера. В первой версии нужен только
небольшой порт сохранения:

```ts
export interface SaveStorage {
  load(): SaveData | null;
  save(data: SaveData): void;
  clear(): void;
}
```

Реализация `LocalStorageSaveStorage` знает о `localStorage`, а доменные правила
не знают.

## 5. Сцены

### `BootScene`

- загружает ассеты;
- показывает состояние загрузки;
- запускает `GameScene` и `UIScene`.

### `GameScene`

- создаёт этаж;
- создаёт игрока, стража и интерактивные объекты;
- настраивает физику;
- обновляет контроллеры;
- управляет безопасной комнатой и переходом этажа.

### `UIScene`

- работает поверх `GameScene`;
- показывает состояние фонаря, найденный ключ и тревогу;
- содержит мобильные кнопки;
- не принимает решений о правилах игры.

Меню, пауза и финальный экран добавляются позже, когда действительно нужны.

## 6. Игровой цикл

Собственный `requestAnimationFrame` не создаётся. Используется Phaser:

```ts
export class GameScene extends Phaser.Scene {
  update(_time: number, deltaMs: number): void {
    const delta = Math.min(deltaMs, 50);

    this.inputController.update();
    this.playerController.update(delta);
    this.guardianController.update(delta);
  }
}
```

Для движения используются velocity и Arcade Physics. Отдельный фиксированный
цикл поверх Phaser не нужен, пока в игре нет детерминированной сложной физики.

Позиция игрока хранится в мировых координатах, а клетка вычисляется:

```ts
const tileX = Math.floor(worldX / TILE_SIZE);
const tileY = Math.floor(worldY / TILE_SIZE);
```

Стены могут строиться по сетке, но физическое тело игрока движется непрерывно.
Pathfinding стража возвращает последовательность клеток, которую
`GuardianController` преобразует в плавное движение к очередной точке.

Процедурная генерация должна быть детерминированной относительно seed, но
реальное движение и визуальные эффекты могут использовать обычный `delta`.

## 7. Состояние

Необходимо разделять сохраняемые данные и runtime-объекты.

### Сохраняется

```ts
export interface GameSessionState {
  runSeed: string;
  floorIndex: number;
  checkpointId: string;
  hasKey: boolean;
  weaponCharges: number;
}
```

### Состояние текущего этажа

```ts
export interface FloorState {
  seed: string;
  width: number;
  height: number;
  keyCollected: boolean;
  doorOpened: boolean;
  secretFound: boolean;
}
```

### Не сохраняется

- Phaser Scene;
- Sprite/Image;
- физические тела;
- клавиши;
- tweens;
- ссылки на DOM;
- обработчики событий.

`SaveData` содержит номер версии для будущих миграций.

## 8. Конечный автомат стража

```text
dormant → pursue → search → pursue
    ↑         │         │
    └──────── safe room ┘
```

Состояния:

- `dormant` — страж временно спит после безопасной комнаты;
- `pursue` — медленно идёт к известной позиции игрока;
- `search` — движется к последней позиции, где видел свет, и ищет рядом.

Правила:

- включённый фонарь регулярно обновляет известную позицию игрока;
- выключение фонаря не телепортирует и не останавливает стража;
- в темноте страж идёт к последней известной позиции и теряет точность;
- при входе игрока в безопасную комнату страж переносится в дальнюю допустимую
  область вне камеры и переходит в `dormant`;
- после выхода игрок получает короткую фору, затем состояние меняется на
  `pursue`;
- страж никогда не переносится в видимой области;
- алгоритм не должен создавать мягкую блокировку выхода из безопасной комнаты.

## 9. Ввод

`InputController` объединяет устройства:

```ts
export interface InputState {
  moveX: number;
  moveY: number;
  interactPressed: boolean;
  toggleLightPressed: boolean;
  useWeaponPressed: boolean;
}
```

Клавиатура и сенсорный UI формируют одинаковый `InputState`. Игровые системы не
проверяют конкретные клавиши или DOM-события.

## 10. События

Глобальная шина событий не нужна. Допустим небольшой типизированный канал между
`GameScene` и `UIScene`.

Первоначальные события:

- `light-changed`;
- `key-collected`;
- `guardian-alert-changed`;
- `checkpoint-entered`;
- `player-caught`.

События не используются вместо обычных вызовов функций внутри одной системы.

## 11. Правила зависимостей

```text
main → scenes
scenes → domain, world, systems, services
systems → domain, world
world → Phaser
services → browser APIs
domain → ничего внешнего
```

Запрещено:

- импортировать Phaser в `domain/`;
- обращаться к `localStorage` из сцены или доменных правил;
- импортировать сцену из доменного модуля;
- помещать игровые правила в UI;
- создавать абстракции для предполагаемого сервера или мультиплеера;
- создавать базовый `Component`, `EntityManager` или ECS без подтверждённой
  необходимости;
- дублировать игровой цикл Phaser.

## 12. Как не переусложнить

Применяем правило трёх:

- не создаём общий интерфейс после одного использования;
- не создаём базовый класс до появления трёх действительно похожих реализаций;
- не выносим функцию из сцены, если она короткая, локальная и не содержит
  отдельного правила;
- не создаём систему «на будущее».

Целевая архитектура первой вертикальной версии:

```text
BootScene
GameScene
UIScene
InputController
LightController
GuardianController
несколько чистых функций domain
```

Этого достаточно для первого ручного тестового уровня.
